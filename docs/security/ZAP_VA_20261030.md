# Analisis dan kontrak remediasi VA ZAP — 30 Oktober 2026

## Batas bukti dan rilis

Masukan adalah laporan PDF ZAP 2.17.0 sepanjang 54 halaman, dibuat 30 Oktober 2026 pukul 09.39 WIB. Ringkasannya memuat dua jenis High, satu Medium, tiga Low dan tujuh Informational; jumlah jenis alert berbeda dari jumlah instance. PDF asli dan hasil ekstraksi lengkap dipertahankan sebagai evidence lokal, bukan dikirim ke Git. Status source, CI, image dan aktivasi VPS harus dibuktikan terpisah pada `.tmp/va-20261030/`; dokumen ini menetapkan analisis dan acceptance criteria, bukan klaim deployment.

Laporan mencampur PORPROV dengan Google/Chrome dan tile OpenStreetMap. Tidak melakukan pentest aktif atau mengubah layanan pihak ketiga. Temuan asli tidak dihapus, diturunkan severity-nya, atau disembunyikan melalui filter alert agar laporan tampak nol. Pengujian ulang harus mempunyai konteks target `https://porprov.depok.go.id/`, dengan daftar pengecualian host eksternal yang eksplisit sebagai batas otorisasi, bukan penekanan alert pada target PORPROV.

## Seluruh High, Medium dan Low

| High Path Traversal, ID 6, h.4–5, satu instance | POST `/analytics/api/collect`, `language=collect`; kolom Evidence kosong | Kolektor tidak membuka file dari field tersebut: tujuan upstream tetap `/api/send`. Regex lama menerima kata tak terdaftar sebagai bahasa. Hardening memakai parser BCP 47 `golang.org/x/text/language` terpin, pembatas panjang serta karakter, tanpa blacklist kata `collect`. Nilai tak sah ditolak 400 deterministik sebelum upstream; locale browser, region/script, ekstensi Unicode dan tag legacy/private yang valid tetap diterima. Ini gap validasi metadata, bukan bukti pembacaan file server. |
| High SQL Injection, ID 40018, h.6, parameter `q` | GET `/api/v1/schedule/periods`, pasangan `AND 1=1 --` / `AND 1=2 --` | Source mengikat nilai pencarian ke parameter `$3`; hanya identifier sort dari allowlist yang disusun dalam query. Reproduksi production sebelum patch menghasilkan 200, total0 dan hash body identik untuk kedua kondisi maupun payload kutip. Pencarian biasa masih bekerja. Regresi PostgreSQL TEMP membuktikan string SQL hanya dapat cocok dengan teks literal fixture, tanpa mengubah predikat. Tidak menambah WAF/blacklist SQL yang merusak pencarian apostrof. ## Kontrak implementasi dan pengujian

- Locale analitik mempunyai panjang maksimal 255 byte, token karakter BCP 47 dan semantic parse; format TR35 underscore yang bukan kontrak browser tetap ditolak. Parser tidak mengganti nilai bahasa yang diterima sebelum forwarding.
- Error kolektor lokal dan upstream 4xx mempunyai body generik deterministik; status upstream ditahan agar klien tetap dapat menangani penolakan/cache kedaluwarsa. Sukses 200 dan payload cache upstream tidak diubah, dengan no-store.
- Tes menggunakan upstream HTTP mock, bukan Umami production: payload laporan tidak boleh memanggil upstream, sedangkan locale browser valid tetap menghasilkan 200. Tidak membuat fixture akun atau mengubah data bisnis production.
- SQL diuji pada PostgreSQL terisolasi menggunakan TEMP table/savepoint/rollback. Nilai boolean SQL dan apostrof diperlakukan sebagai string literal; baseline, calendar/day count, pagination, soft delete, revisi dan outbox tetap berlaku.
- Protected CI pada SHA final: test/build, govulncheck, secret scan, CodeQL, dependency review dan security gates; image Gateway terdampak memiliki SBOM dan scan seluruh severity tanpa exception baru. Jangan mengulang full suite lokal yang tidak terpengaruh.
- Production: preflight read-only, backup/checksum/off-host dan rehearsal pemulihan; deploy hanya Gateway stateless, kemudian reload Nginx untuk DNS upstream. Tidak menjalankan migrasi/bootstrap, mengganti credential, mengaktifkan modul yang sengaja off, menghapus volume atau mengubah konten.
- Retest payload invalid di VPS harus 400/403 deterministik, tanpa database write. Event analitik normal dibuktikan dengan upstream mock dan pengamatan aplikasi normal; jangan mengirim event pentest valid massal yang mencemari statistik production. ZAP pasif target-only melengkapi regresi terarah; bukan pengganti pentest aktif terautentikasi menyeluruh.
- Rollback memakai source/image/config sebelumnya tanpa schema down atau restore database untuk hotfix stateless ini. Health dan HTTP frontend merupakan pemeriksaan berbeda; 404/403 modul Public yang dinonaktifkan pemilik adalah hasil yang benar.
